# Scenario: the secret the output does not hide

**Exam objective: 2f (managing sensitive data), building on 2e (declaring variables and outputs, complex types).**

A password generated by Terraform must leave the project, but without ending up in cleartext where it is not expected. The learner must demonstrate, with evidence, what `sensitive = true` really masks and what it does not, expose a fingerprint without disclosing the secret, and lock the module with a `precondition` carried by an output.

## Target capability

Expose the results of a configuration while mastering the real arguments of the `output` block: `value`, `type` (type constraint, Terraform 1.15), `sensitive`, and `precondition`. Know that sensitivity **propagates**, even through a function: the `sha256` of a secret stays sensitive, and exposing it requires an explicit declassification with `nonsensitive()`. Above all, know that `sensitive` only affects display: the value stays in cleartext in the state, in `terraform output -json` and in `terraform output -raw`.

## Where the learner starts

`challenge/work/` holds an incomplete project. No VM, no remote account: only `hashicorp/random` and `hashicorp/local` are used, `terraform init` is already run and `.terraform.lock.hcl` is in place. The lab runs anywhere `terraform` 1.15 or later is on the PATH, offline.

The directory has `versions.tf` (already correct, `required_version = ">= 1.15.0"`), `variables.tf` with `longueur_mot_de_passe` (number, default 24), `main.tf` (provided) declaring `random_password.admin` and a **non-secret** `local_file.rapport` (it only writes the length), and a holed `outputs.tf`:

```hcl
output "mot_de_passe_admin" {   # type string, SENSITIVE VALUE
  ???
}
output "resume" {               # object({ longueur = number, empreinte = string })
  ???                           # empreinte = sha256 of the secret, WITHOUT disclosing it
}
output "empreinte_rapport" {    # sha256 of the report content
  value = sha256(local_file.rapport.content)
  ???                           # a precondition to write
}
```

`terraform plan` fails as-is: the `???` are not valid HCL, and an output referencing the secret without `sensitive` would be rejected anyway.

## The state to reach

1. `mot_de_passe_admin` carries `type = string`, `sensitive = true` and exposes `random_password.admin.result`. Without `sensitive`, the plan is rejected ("Output refers to sensitive values").
2. `resume` carries the constraint `type = object({ longueur = number, empreinte = string })` and is **not** sensitive. `empreinte` is the `sha256` of the password, but since the `sha256` of a secret stays sensitive, the learner must declassify it with `nonsensitive()`. No value of the object is the secret.
3. `empreinte_rapport` carries a `precondition` block with its mandatory `error_message`, requiring `var.longueur_mot_de_passe >= 20`.
4. The project converges: a second plan right after apply proposes nothing.

## How it is proven

The tests never open the learner's `.tf` files and parse no human output. They drive Terraform in `challenge/work` and read only JSON or return codes.

1. `terraform output -json`: `mot_de_passe_admin` has `"sensitive": true` and its `value` holds the **cleartext** string, length 24. This is the lab's central demonstration.
2. `terraform show -json`: `random_password.admin` exposes under `values.result` the exact same string. The state keeps the secret in cleartext, `sensitive` or not.
3. `terraform output -raw mot_de_passe_admin` returns the same string: `-raw` lifts the redaction just like `-json`.
4. In `terraform output -json`, `resume` is not sensitive, is an object with keys `longueur` (24) and `empreinte` (64 hex characters), and no value equals the password.
5. `empreinte_rapport` is a 64-character `sha256`.
6. `terraform plan -var 'longueur_mot_de_passe=8'` exits non-zero: the output's `precondition` blocks the plan.
7. `terraform plan -detailed-exitcode` returns 0 right after apply. A code 2 fails the lab.
